# Handoff: сокращение визуального контракта клетки

Дата: 2026-09-22.

Исходный запрос: проверить [CELL_TYPE_MAP.md](CELL_TYPE_MAP.md), установить реальные дубли, неиспользуемые данные и минимальные независимые свойства клетки.

## Статус и границы выполненной работы

Аудит выполнен по исходникам текущего рабочего дерева, включая незакоммиченный `CellVisualProtocol.cs`. Проверены потребители в C#, производственных шейдерах, тестах и локальном исходнике пакета протокола. Списки типов и повторяющиеся RGB-записи дополнительно сравнены скриптом без изменения файлов.

Код не менялся. Unity, сборка, тесты и GPU-проверка не запускались. Этот handoff фиксирует выводы и возможный порядок рефакторинга; текущий запрос пользователя — написать документ.

До создания handoff рабочее дерево содержало:

```text
 M Assets/Scripts/World/Storage/MapCellConfigCatalog.cs
?? Assets/Scripts/World/Storage/CellVisualProtocol.cs
?? Assets/Scripts/World/Storage/CellVisualProtocol.cs.meta
?? CELL_TYPE_MAP.md
```

Это существующие пользовательские изменения. Их нельзя откатывать или перезаписывать. Перед реализацией прочитать актуальный [AGENTS.md](AGENTS.md). В частности, операции Unity, commit/push и rollback ограничены отдельными правилами проекта. Создание этого документа их не разрешает.

## Основной вывод

В исходной карте смешаны три разных случая:

1. Данные без потребителей, которые не нужны новому контракту.
2. Несколько источников одного решения, которые нужно свести к одному итоговому значению.
3. Независимые свойства, которые нельзя объединять на основании сходных названий или пересечения списков типов.

Пометка «рендер» сама по себе не означает «лишнее». Перенос нужного значения из серверной конфигурации в клиентский каталог должен сохранить источник этого значения и его потребителей.

## 1. Геометрия: исправить модель из CELL_TYPE_MAP

Источники:

- [TerrainVertexDistortionCalculator.cs](Assets/Scripts/World/Terrain/Mesh/TerrainVertexDistortionCalculator.cs): `IsCause`, `IsBlock` по серверному `Distortion`.
- [CellVisualProtocol.cs](Assets/Scripts/World/Storage/CellVisualProtocol.cs): четыре набора типов.
- [TerrainSheetCatalog.cs](Assets/Scripts/World/Terrain/Mesh/TerrainSheetCatalog.cs): выбор непрерывного листа.
- [TerrainSampling.hlsl](Assets/Shaders/TerrainSampling.hlsl): фактическая адресация текстуры.

Участие в смещении общих узлов определяет серверный `Distortion`:

```text
IsCause = Distortion == Cause
IsBlock = Distortion == Block
```

`Neutral` и влияние соседей сохраняются. Клиентский признак мягкого контура больше не останавливает смещение узлов; для этого сервер задаёт `Block`.

`ContinuousSheet` определяет UV-адресацию. Семь типов `Alive*` одновременно используют непрерывный лист и серверный `Distortion=Block` в локальной симуляции.

Результат сравнения наборов:

| Набор | Количество типов |
| --- | ---: |
| RoundableLoose | 14 |
| Road | 4 |

Списки фиксированной геометрии и инфраструктурных блоков удалены. Смещение задаёт серверный `Distortion`, отсутствие фаски — серверный `ReliefGroup=0`.

Предложенный `Surface: обычная / мягкая / дорога` также объединяет разные решения: скругление контура и участие в физической массе для света.

## 2. Рельеф: целая цепочка осталась ради диагностики

Текущая цепочка:

```text
packet.ReliefGroup
  → CellMetadata / CachedCellData
  → CalculateReliefMask / CellReliefMasks
  → TerrainReliefRimCatalog / hasRelief
  → TerrainLightingData.Pack / reliefCode
  → отладочные виды рельефа
```

В [Terrain.shader](Assets/Shaders/Terrain.shader) обычный проход больше не умножает альбедо на кайму. Единственный вызов `TerrainReliefRim(surface)` находится в [TerrainDebugView.hlsl](Assets/Shaders/TerrainDebugView.hlsl). Декодирование `reliefCode` обслуживает эту функцию и отладочные виды чужих сторон/кода рельефа. В производственном освещении другого потребителя найдено не было.

Следовательно, расчёт и транспорт рельефа — кандидат на удаление вместе с соответствующей диагностикой. Это отдельное изменение функциональности отладчика, а не полностью неиспользуемый код. Альтернатива при сохранении диагностики — вынести расчёт в её собственный путь с корректным обновлением данных при включении вида.

Если цепочку сохранять, её классификацию всё равно можно сократить:

- `ParticipatesInRim` возвращает `true` для всех шести содержательных семейств; `false` получает только `None`, соответствующий `Unloaded`.
- `IsRock` содержит одинаковые десять типов в `TerrainSheetCatalog` и [TerrainReliefRimCatalog.cs](Assets/Scripts/World/Terrain/Mesh/TerrainReliefRimCatalog.cs).
- Различие Rock/Crystal ещё используется внутри `SameReliefSurface` для непрерывных листов. Его нельзя удалить из сохранённого расчёта маски без замены.
- Текущее соединение поверхностей учитывает равенство ненулевых `ReliefGroup` либо принадлежность обоих листов одному семейству. Простая подмена этого отношения одним новым номером группы требует отдельной проверки.

При полном удалении цепочки учесть настройку `EnableReliefRim`, публикацию `_TerrainReliefRimEnabled`, упаковку битов и отладочные режимы. `TerrainSheetCatalog` целиком не удалять: адресация UV остаётся действующей.

## 3. Декали: DecalFamily не нужен как поле каждой клетки

Источники: [TerrainDecalCatalog.cs](Assets/Scripts/World/Terrain/Mesh/TerrainDecalCatalog.cs), `TerrainQuadBuilder.FillQuad`.

Производственный путь вызывает `GetGroundPlacement`, который всегда передаёт `CellType.Empty` в `GetPackedPlacement`. Поэтому размещение использует только семейство Ground.

Ветки размещения Stone/Sand/Road, их варианты и `PlacementPercent = 30` не имеют игрового вызова. Тесты вызывают их напрямую, что не делает эти ветки частью игрового пути.

`GetFamily` дополнительно используется каталогом каймы для определения Sand. Сначала убрать или заменить эту зависимость, затем сокращать семейства декалей.

Для текущего поведения достаточно правила поверхности грунта/подложки и функции размещения. Сохранить существующие 24%, 16 вариантов, хеш координат, отражения, повороты и смещения. Удаление мёртвых веток не должно менять уже существующее размещение Ground.

## 4. Флаги протокола: не все лишние

| Значение | Что установлено |
| --- | --- |
| `ReceivesShadow` | Удалён из dummy-конфигурации; потребителей в клиентском рендере не найдено. |
| `Blending` | Потребителей значения `CellConfigProperties.Blending` в клиентском рендере не найдено. Не переносить в новый визуальный каталог. |
| `DropsShadow` | Используется в `CalculateSolidBoundaryMask`; стороны соседства влияют на `EvaluateRoundableBlockAlpha`. Сохранить это решение или явно заменить его источник. |
| `Glowing` | Определяет включение эмиссии напрямую. Значение нужно. |
| `Passable`, `Breakable` | Игровые свойства. Не заменять их визуальными категориями. |

`DropsShadow` и `PhysicalMass` сегодня не эквивалентны. Масса определяется как непустой передний план, исключая Road-типы. Например, Gate и TeleportBlock в dummy-конфигурации не имеют DropsShadow, но проходят проверку физической массы. Объединение этих решений изменит поведение; это не чистое удаление дубля.

`CellConfigurationPacket` сериализуется как структура с `Pack = 1` через `UnsafeWrite/UnsafeRead`. Удаление полей и изменение численных значений wire-enum нельзя выполнять только на клиенте. Отсутствие читателей двух флагов не разрешает менять раскладку сетевого пакета.

## 5. Дубли и неиспользуемые биты в данных GPU

Источники: [TerrainLightingData.cs](Assets/Scripts/World/Terrain/Mesh/TerrainLightingData.cs), [TerrainLightingData.hlsl](Assets/Shaders/TerrainLightingData.hlsl), [TerrainContour.hlsl](Assets/Shaders/TerrainContour.hlsl).

- Скругление пишется в `RoundedPhysicalContour` внутри `PackedFlags` и в `RoundableContourFlag` внутри `PackedContour`. Производственный контур читает второй вариант. У `KernTerrainHasRoundedPhysicalContour` вызовов не найдено.
- Свечение повторно пишется в `GlowingContourFlag` — бит 0 `PackedContour`. Читателя этого бита не найдено; действующая эмиссия читает `Emissive` из `PackedFlags`.
- Диагональное соседство пишется в биты 2–5 `PackedContour`. `KernTerrainSolidDiagonal` не вызывается; C#-декодирование используется тестами.
- Четыре прямые стороны соседства живые: их использует скругление контура.
- Биты рельефа рассматривать вместе с решением о сохранении его диагностики.

Сокращать упаковку согласованно в C# и HLSL, включая видимый проход, поле материалов и декодирование CPU. Это внутренний формат обмена с GPU, а не отдельный источник визуальных свойств.

## 6. Цвета: палитра клиента — источник правды, а не дубль серверных данных

Источники: [MapBlockColors.cs](Assets/Scripts/World/Common/MapBlockColors.cs), [DummyMapColors.cs](Assets/Scripts/Networking/Connection/Client/Simulation/DummyMapColors.cs), [DummyCellConfigurationUtilities.cs](Assets/Scripts/Networking/Connection/Client/Simulation/DummyCellConfigurationUtilities.cs), а на сервере — `NewMinesServer/MinesServer/Server/ProtocolWorld.cs` и `Game/World/Cell.cs`.

**Прежний вывод раздела был неверен.** Запись шла: таблица — дубль серверных цветовых данных, кандидат на удаление, сервер — источник правды. Фактически сервер цвета клеток не моделирует: в `Cell.cs` (47 строк) нет поля цвета, в `cells.json` его нет, а `ProtocolWorld.BuildCellConfigurations` кладёт `unchecked((int)0xFFFFFFFF)` в `Color` для всех 256 типов. Клиент разворачивал это в белый — обе карты становились полностью белыми.

Дубль `DummyMapColors`/`ApplyMapColors` больше не дублирует серверные данные: он кладёт палитру в серверное поле, которое клиент для описанных типов не читает. Функционально безвредно, но и бессмысленно.

`Color` нельзя просто заменить средним цветом PNG: он используется для карты и диагностики, его RGB попадает в параметры цветового эффекта, а alpha участвует в мощности эмиссии. При этом в текущем проходе поля материалов RGB эмиссии получается из обработанного альбедо. Утверждение «цвет всего света напрямую равен packet.Color» остаётся устаревшим и переносить его в новый контракт нельзя.

Текущее состояние палитры: точные `Color32` (прежнее хранение в `Color` через `/256f` срезало по единице в каждом ненулевом канале), `IsAuthored` на каждый тип, 12 ранее отсутствовавших цветов дописаны, неназванные значения дают magenta «нет данных» вместо градиентной формулы. Полноту палитры держит тест `MapBlockColorsTests` — он падает, когда пакет `darkar25.fodinae.data` добавляет новую породу.

## 7. Новый CellVisualProtocol пока не устраняет источники дублей

Источники: [CellVisualProtocol.cs](Assets/Scripts/World/Storage/CellVisualProtocol.cs), [MapCellConfigCatalog.cs](Assets/Scripts/World/Storage/MapCellConfigCatalog.cs).

`GetVisualProperties` используется рендером; `CellVisualProtocolRegistry.Replace` пока не вызывается. Реализация оборачивает четыре клиентских списка; каталоги листов, анимации и декалей остаются отдельными.

Есть два потенциально расходящихся способа чтения:

```text
экземпляр MapCellConfigCatalog → provider, запомненный в конструкторе
статические методы каталога   → Registry.Current на момент вызова
```

Переданный в конструктор другой provider не влияет на статических потребителей. Замена Registry после создания каталога также не обновит сохранённый provider; инвалидирование готовых terrain-метаданных с Replace не связано.

Рекомендация: один источник описаний и один используемый путь доступа. Не сохранять Registry, Replace и неиспользуемый экземплярный API только ради возможного будущего сервера. Если смена источника становится реальной задачей, отдельно определить жизненный цикл и обновление зависимых кэшей.

Серверные `Glowing` и `ReliefGroup` определяют свечение и наличие фаски. Локальная симуляция задаёт блокам без фаски `ReliefGroup=0`; реальный серверный конфиг требует того же значения.

## 8. Анимация и текстурная разметка

Источники: [TerrainAnimationProfile.cs](Assets/Scripts/World/Terrain/Mesh/TerrainAnimationProfile.cs), [TerrainColorAnimation.hlsl](Assets/Shaders/TerrainColorAnimation.hlsl), [WorldTextureManager.cs](Assets/Scripts/World/Textures/WorldTextureManager.cs).

Специальные клиентские профили выбирают собственный эффект и скорость для пяти X-кристаллов, Lava и шести обычных кристаллов. В выборе цветового эффекта они приоритетнее packet.Animation. Это кандидат на одно итоговое описание эффекта вместо передачи двух конкурирующих классификаторов.

Однако анимация включает несколько решений: цветовой эффект, выборку flow-map, UV-скроллинг и смену кадров. При сокращении сохранить каждое из них. В частности, старое числовое значение Animation=4 читается шейдером как скроллинг, хотя его нет среди именованных значений загруженного enum.

`FrameOffset` в текущем клиенте задаёт высоту кадра в клетках:

```text
frameHeight = FrameOffset * CELL_SIZE
frameCount = frameHeight > 0 ? texture.height / frameHeight : 1
```

Следовательно, «клиент знает число кадров по текстуре» в исходной карте неполно. Нужна разметка кадров, сейчас приходящая из пакета. В клиентском описании ей подходит явное имя высоты кадра. Не объявлять отсутствие анимации по единственному кадру: цветовой эффект может работать на статической текстуре.

Дополнительный небольшой кандидат: `AnimateTerrainSampleUV` принимает пять аргументов и просто возвращает входной `atlasUV`. Вызовы в обоих проходах можно заменить прямым использованием результата `ResolveTerrainTileUV`, сохранив последующие поправку пиксельной сетки и ограничение UV.

## Минимальные независимые решения

Это смысловые составляющие, а не требование создать отдельный класс или enum для каждой строки.

| Решение | Источник / ограничение |
| --- | --- |
| Игровой тип, проходимость, разрушаемость, движение | Серверные данные; визуальные признаки их не заменяют. |
| Режим деформации | Серверный `Distortion` без клиентских ограничений. |
| Скругление контура | Отдельное свойство; альфа-силуэт берётся из текстуры. |
| Адресация текстуры и группа автотайлинга | Явное описание; размер PNG не определяет способ соединения соседей. |
| Участие в массе для света и в соседстве контура | Пока сохранить как разные решения: текущие правила расходятся. |
| Эмиссия и цветовые параметры | Итоговые значения с сохранением ролей RGB/alpha и правил слоёв. |
| Цветовой эффект, UV-анимация, разметка кадров | Разрешить источники заранее; не терять независимое покадровое воспроизведение. |
| Размещение грунтовых декалей | Правило слоя/поверхности; отдельное DecalFamily для каждого CellType не требуется. |
| Рельеф | Только при сохранении соответствующей диагностики. |

Alpha, `IsFullyOpaque`, `AtlasRect`, `AtlasIndex`, `UVTileSize` и производные размеры относятся к текстуре и её размещению. Не вводить вторую авторскую таблицу для уже вычисляемых величин. `IsFullyOpaque` — агрегат для отсечения подложки, он не определяет правила деформации.

`CellMetadata`, `CachedCellData` и упакованные данные GPU не считать автоматически лишними копиями: это подготовленные представления для разных этапов. Сокращение источников истины не должно заменять кэширование поиском по каталогам на каждую клетку или вершину.

## Порядок продолжения

1. Перепроверить рабочее дерево и актуальные вызовы: handoff отражает состояние на дату аудита.
2. Исправить смысловую карту: разделить независимые решения и пометить диагностические/неиспользуемые ветки.
3. Начать с сокращений без изменения игровых правил: перезаписываемые color-аргументы, неиспользуемые цветовые таблицы и API, пустая UV-обёртка, повторные перечисления.
4. Отдельно определить судьбу отладочных видов рельефа. Затем сокращать цепочку рельефа и зависимость от семейств декалей.
5. Свести визуальные решения к одному реально используемому каталогу. Разрешать значения при подготовке метаданных, сохраняя нужные кэши.
6. Согласованно сократить упаковку CPU/GPU и проверить действующие декодеры.
7. Перенос полей из wire-протокола рассматривать отдельной задачей совместимости клиента и сервера.

Не объединять весь объём в механическое удаление найденных имён: часть методов используется тестами и диагностикой, часть значений имеет два разных смысла, а некоторые свойства важны только для сочетания слоёв.

## Проверка после реализации

Разрешённые без управления Unity проверки: поиск оставшихся потребителей, проверка границ сборок, локальные проверки чистой логики и форматов. В репозитории есть `tools/Kern.TerrainTests` и `tools/Kern.TerrainBench`; перед использованием проверить их состав исходников и доступность зависимостей. Новый файл, связанный с каталогом, может потребовать включения в проекты с явным списком Compile.

Приоритетные сценарии:

- Neutral/Cause/Block и соседство со скругляемой клеткой.
- `Alive*`: одновременно серверный `Block` и непрерывный лист.
- BuildingRoad, Gate и TeleportBlock: различия дороги, массы и соседства.
- Альфа-дырки и выбор подложки под непрозрачной, скруглённой и смещённой клеткой.
- Детерминированное размещение Ground до/после сокращения декалей.
- Сохранение RGB/alpha и преобразований цветовых таблиц.
- Цветовая анимация на одном кадре, многокадровые текстуры и скроллинг.
- Согласованность упаковки и декодирования битов; отсутствие потерянных потребителей.
- Сохранённые отладочные виды, если принято решение их оставить.

Статический анализ, CPU-модель и тест упаковки не доказывают визуальную эквивалентность. Для изменений геометрии, UV, контура и GPU-данных остаётся проверка через производственные shader/pass, реальные атрибуты меша и SV_POSITION, material keywords, data textures и путь камеры/проекции. Нужен независимый визуальный эталон. Конкретную операцию Unity выполнять только при её явном разрешении пользователем.

На момент handoff такая проверка не выполнена; отсутствие визуальных изменений после будущего рефакторинга не заявляется.
