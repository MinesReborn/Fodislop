План структурного рефакторинга Kern

Цель: сделать файловую структуру отражением владения кодом, границ asmdef и жизненного цикла, не меняя Unity-ассеты текстом и не трогая NC.cs.

Выполнено

Инвентарь разделён по ответственности: состояние и контракт находятся в Game/Inventory, presentation — в UI/Inventory. Удалён мёртвый InventoryDragAndContextMenu; context menu встроено в InventoryView.

Алгоритм фоновой заливки перенесён из общего World/Rendering в World/Terrain/Background; profiler marker приведён к тому же имени.

ShaderWarmupService перенесён из Core/Bootstrap в Core/Rendering: composition root больше не выглядит владельцем rendering-сервиса.

RuntimeAssetPaths перенесён из Core/Diagnostics в AssetPipeline/Loading; в Diagnostics оставлены только диагностические типы.

Добавлен gate Unity Editor: проект требует 6000.6.0f1 или новее.

Следующий этап

  2. Сократить технические каталоги Core и оставить в них только реально shared-контракты и application lifecycle.

Ограничения

Сцены, prefab, material и asset YAML меняются только через Unity Editor по явному запросу. Пользовательские изменения вне структурного рефакторинга сохраняются без вмешательства.
