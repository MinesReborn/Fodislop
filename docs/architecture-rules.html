Kern architecture rules

The project currently uses two complementary linters. The C# runner in tools/Kern.ArchitectureLinter owns migrated source and IL contracts. scripts/check-architecture.js still owns non-migrated scene, design-system, localization, and debt-budget checks. Neither runner is described as a full replacement until the remaining checks have actually moved.

Running

dotnet run --project tools/Kern.ArchitectureLinter -- -p .
dotnet run --project tools/Kern.ArchitectureLinter -- -p . --rule KERN-DISPLAY-TRANSFORM
dotnet run --project tools/Kern.ArchitectureLinter -- -p . \
  --rule KERN-DISPLAY-TRANSFORM --rule KERN-POSTPROCESS-RUNTIME

--rule is repeatable and rejects unknown IDs. With no selector, every discovered rule runs. Source-only selections do not load compiled assemblies. IL selections discover assemblies by simple name, prefer Temp/bin over Library/ScriptAssemblies and build, and avoid scanning a stale monolithic Assembly-CSharp.dll beside modular Kern.* assemblies.

The local pre-commit hook runs the migrated source-based display, localization, and architecture-pattern rules. Runtime IL rules run in CI only after a successful current C# build, so stale Editor output cannot decide the result.

Display and IMGUI contracts

KERN-DISPLAY-TRANSFORM

  • D65-preserving output-gamut matrices and inverse LMS transforms.
  • Norm-based tone curve, neutral ASC CDL behavior, HDR headroom and hue preservation.
  • Output-gamut conversion before temporal history and explicit SDR gamma.
  • Vignette coordinates, scopes signal scaling, active-color texture descriptors, and debug temporal bypass.

KERN-POSTPROCESS-RUNTIME

  • ToolWindows.Unregister releases IMGUI input capture.
  • PostProcessController.OnDisable resets bypass and advanced runtime settings.
  • Render feature and scopes pass use the explicitly tracked main camera.
  • HDR enablement updates the platform output in both state branches.

Adding a C# rule

  1. Add a public, non-abstract class implementing IRule under the rules directory.
  2. Give it a public parameterless constructor and a unique stable ID.
  3. Override RequiresAssemblies with false when it reads only source files.
  4. Add the rule to this index and wire a selective pre-commit or CI invocation only after its existing violations are understood.

Rules are discovered from the linter assembly through reflection. There is no manual registry in CreateDefaultRules().

Transition boundary

The JavaScript runner remains authoritative for checks that have not been migrated. A check must have one owner: once a contract is represented in a C# rule and invoked by the hook, its duplicate JavaScript implementation is removed. The entire legacy C# suite is not enabled as a blocking hook in one step because existing false positives and debt first need rule-by-rule correction.
