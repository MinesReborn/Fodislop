Kern Architecture Linter

tools/architecture/Kern.ArchitectureLinter is the project's architecture rule runner. The former scripts/check-architecture.js is not present. Rules are discovered from non-abstract IRule implementations in the linter assembly; this page deliberately does not keep a second, manually maintained rule index.

Run rules

dotnet run --project tools/architecture/Kern.ArchitectureLinter/Kern.ArchitectureLinter.csproj -- \
  --project-root . --source-only --fail-on Error

dotnet run --project tools/architecture/Kern.ArchitectureLinter/Kern.ArchitectureLinter.csproj -- \
  --project-root . --rule KERN-DISPLAY-TRANSFORM

dotnet test tools/architecture/Kern.ArchitectureLinter.Tests/Kern.ArchitectureLinter.Tests.csproj
  • With no --rule selector, --source-only runs rules whose RequiresAssemblies is false and skips assembly loading. If you explicitly select an assembly-dependent rule, it still runs and needs assemblies.
  • Without --source-only, assembly-based rules discover Unity outputs under Temp/bin, Library/ScriptAssemblies, and build. If modular Kern.* assemblies exist, discovery excludes monolithic Assembly-CSharp.dll.
  • Repeat --rule <id> to select rules. Unknown IDs fail. With no selector, all discovered rules run.
  • --fail-on Error|Warning|Info sets the exit threshold; --strict treats warnings as errors. --sarif [path] writes SARIF.

The runner exits 0 when no violation meets the threshold, 1 when findings meet it, and 2 for configuration or execution failure. Source-only lint is not proof that assembly-based rules ran.

Repository wiring

scripts/run-ci.sh runs linter tests, source-only lint, standalone tests, selected tool builds, and lighting/crystal/raster harnesses. The local pre-commit hook calls this full script through .pre-commit-config.yaml; it is not a narrow architecture-only hook. GitHub Actions currently exposes only a manual workflow, and its unified-ci job is disabled by if: false; push/PR checks do not run automatically.

Add a rule

  1. Implement IRule in tools/architecture/Kern.ArchitectureLinter/Rules/ with a public parameterless constructor, a stable unique Id, a description, severity, and EvaluateAsync.
  2. Set RequiresAssemblies to false only when the rule needs no compiled assemblies; source-only runs filter by this property.
  3. Add focused scenarios under tools/architecture/Kern.ArchitectureLinter.Tests/. Rule discovery needs no manual registry or duplicated HTML index.
  4. Run the focused tests and the applicable source-only or assembly-backed rule command. Do not describe a rule as covered by CI unless it is invoked by the actual workflow.
