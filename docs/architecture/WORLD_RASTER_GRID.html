Мировая растеризация 32 px/клетку

Текущее состояние реализации, сверено по исходникам 8 ноября 2026. Владелец — presentation, PostProcessRendererFeature. Растеризация Renderer2D получает один мировой буфер с плотностью 32 пикселя на клетку. Размеры округляются наружу, с одним защитным пикселем на каждой стороне. GPU projection отображает эти границы в буфер; точечное представление выбирает исходный видимый прямоугольник. Свойства Camera используются для чтения границ и не изменяются.

Цветовой формат presentation наследуется от источника. Цветовая конверсия и HDR encoding остаются в URP. Новых lighting solves, подписок или вызовов terrain collection нет.

Геометрия растеризуется через frame-local descriptor и GPU matrices; Camera остаётся источником viewport/input и её свойства не переписываются. Point presentation после postprocessing возвращает world image к display target до UI.

Стоимость — TL-PERF

Мировой буфер имеет W = ceil(maxX·32) − floor(minX·32) + 2, H = ceil(maxY·32) − floor(minY·32) + 2. При видимых 16×16 клетках это 514×514, при 32×32 — 1026×1026. Мировые draw calls исполняются в этом разрешении. Новые операции: одна установка GPU matrices и один экранный draw для point presentation; дополнительных compute dispatch нет. Presentation требует один экранный color target: при RGBA16F это 8·displayWidth·displayHeight байт, без depth и MSAA. Экономия относительно исходного разрешения зависит от zoom и размера экрана и не измерена.

Активное depth-вложение

WorldRasterDepthPass проверяет activeDepthTexture, которое Renderer2D действительно привяжет, включая выбор backbuffer depth. При несовпадении размеров создаётся мировое depth-вложение того же формата и явно выбирается Camera depth. Изолированный адаптер UrpIntegration компилируется через asmref в URP assembly, поскольку селектор internal. Production reflection и правки Camera отсутствуют. Если depth отсутствует, режим без depth сохраняется.

Историческая заметка о тестах из предыдущего снимка сообщает о headless-прогоне MainGame_TerrainRimImage и Surface_RealMeshPass_PreservesHdrAndProducesDepthLayers в копии проекта. Этот результат не является текущей проверкой и не задаёт допустимый workflow: проектные инструкции запрещают запускать проверки на копии. В той записи второй тест проверял обе позиции depth-селектора, включая импортированный depth 3420×1890 без creation descriptor. Отчёт: Logs/Diagnostics/terrain-rim-material-proof/active-depth-results.xml. Исправление не меняет геометрию, освещение или их invalidation; выделение depth выполняется только при реальном несовпадении размеров активного вложения.
