WorldRenderGrid — текущее состояние реализации

2026-09-30. Renderer2D растеризует мир непосредственно в 32 пикселя/клетку. Перестройка всего плана пока не завершена; производительность и полный HDR/UI lifecycle gate не подтверждены.

Контракт изменений и владельцы

Rendering владеет WorldRenderGrid, camera binding, контекстом Renderer2D, color/depth и postprocessing. Видимые terrain/entity/surface и стандартные URP sprite/mask vertex shaders потребляют одну плотность; Effekseer использует Unity backend и те же vertex helpers. Вершины округляются при растеризации, угол робота не округляется. Lighting владеет своей опубликованной текстурой/rect; presentation читает её, Пробы каскадов остаются редкими; поля геометрии, материалов, эмиссии и применения света теперь имеют 32×32 текселя на клетку.

Последовательность: world color/depth → WorldBloom.compute → RGB additive WorldBloomAdd → native URP exposure/tonemapping → DisplayFinal на мировом разрешении → существующий FinalBlit: crop/point enlargement или bilinear reduction, native output encoding и полноразмерный UI. DisplayFinal перенесён на сетку мира согласно уточнению пользователя: все его эффекты должны вычисляться на той же сетке. Camera projection для ввода/UI не изменяется.

Перенос статического атласа — TL-OWN / TL-API / TL-REV / TL-STAGE / TL-DATA

Lighting владеет копией предыдущих transport inputs, scratch interval atlas, картой зависимостей и переносом проб. Terrain публикует через существующий нейтральный exchange симметрическую разность старого и нового contributor coverage, включая исчезнувшие полосы. Новых прямых зависимостей доменов нет. Поле переносится только при сохранённых static/contributor generations и integer texel scale. Каждый каскад отдельно проверяет фазу проб; несовпадающая фаза инвалидирует весь каскад.

Порядок reanchor: копии старых material/emission → production raster новых полей → geometry caches → GPU exact input comparison → горизонтальный/вертикальный prefix scan → перенос соответствующих world probes → far-to-near dependency solve → native resolve/composite → публикация. Ray-box query учитывает изменённые входы, оба края конечного transport domain, поддержку выборки, child intervals и изменившееся clamping topology. Изменения static field не зависят от движения динамического источника. На новом регионе все пересекающиеся pending edits переходят в этот solve; дневной/кадровой квоты на площадь правок нет.

Static DDA принимает точные integer probe anchors и относительные floating offsets. Сдвиг начала поля поэтому не округляет endpoints перед вычитанием. Dynamic path сохраняет точное положение источника. Нет округления радианса, ограничения DDA, пропуска кадров или повторного tonemapping.
