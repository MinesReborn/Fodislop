Статус: код и локальные проверки завершены; production GPU-проверка и измерения времени не выполнены. Изменение не проходит все обязательные merge gates TL-VERIFY / TL-PERF. Устранение фриза 60 мс не подтверждено.

TL-CHANGE / TL-OWN / TL-API: проблема и границы

Пользователь сообщил фриз до 60 мс при копании — это принятый факт. Код ранее очищал и растеризовал всё поле AO при изменении одной клетки. Для окна 192×128 клеток при 32 пикселях на клетку это 6144×4096, 25 165 824 пикселя и 96 MiB ARGB32. Это подтверждённый избыточный объём работы; его доля в 60 мс без GPU-capture не установлена. Material/emission, geometry caches и транспорт освещения по-прежнему могут перестраиваться.

Lighting владеет областью обновления, attachment binding, очисткой, ресурсами и политикой инвалидации. Terrain получает нейтральный borrowed LightingAmbientOcclusionContext.RasterRect из Kern.Contracts и рисует существующим production AO pass. Новый init-only член сохраняет существующий positional конструктор; null означает полное поле. Контракт явно требует сохранения содержимого. Координаты: half-open пиксели render target, начало снизу слева; world rect — Unity world units. Вызов на основном потоке в фазе записи CommandBuffer; handles нельзя удерживать.

TL-PERF: расчёт работы и ограничения

Для единственной записи 1×1 вдали от края область 7×7 клеток = 224×224 = 50 176 пикселей. Это граница покрытия фрагментов, а не измеренный выигрыш GPU: mesh vertex work сохраняется; Load/Store может требовать bandwidth всего target, особенно на tile GPU. Журнал может содержать более широкие регионы. Худший случай union покрывает всё поле плюс один clear draw. Стабильный кадр не добавляет AO draw. Новая память: один Material, ноль textures/buffers. Размер и формат AO не уменьшались.

CPU marker Kern.Lighting.AmbientOcclusion.Record.CPU; GPU markers Kern.Lighting.AmbientOcclusionField.Full / .Partial; FrameEventLog записывает размеры области, число пикселей и размеры поля. Существующие field rebuild reasons и счётчики сохранены.

Baseline runtime: пользовательские 60 мс при копании. После: не измерено. Для performance gate нужны одинаковые сцена/input/resolution/preset до и после: stable frame и одиночное копание, frame-local CPU/GPU stages и pixel coverage. Acceptance: частичный результат совпадает с полным и ни один texel вне области не меняется; уменьшение времени invalidating frame должно превышать разброс повторных замеров при отсутствии роста stable-frame cost. Числовую цель ускорения без baseline capture не заявляем.

Продолжение: зарегистрирован провис 274,9 мс

В Logs/Editor.log:10477 перед сеансом прогрето 194 состояния; первый Bz при копании и частичное AO предшествуют провису 274,9 мс (10582–10587). После него в журнале идут ещё 14 Bz подряд без повторения этого конкретного отчёта. В 10694 сохранено 195 состояний. В текущей записанной коллекции новое состояние — Hidden/Kern/LightingFieldRectClear, GUID 23cae0a6a7b414e7fb16c48d891463dc, pass 0/0, без vertex streams, один attachment, один sample, без depth. Коллекция не изменялась агентом: эти данные записал пользовательский сеанс.

Подтверждённый дефект добавленного пути: shader загружался при создании ресурсов, но его первый draw выполнялся только при первой частичной инвалидации. Resources.Load и создание Material не создают готовый graphics pipeline. Исправление выполняет тот же production clear draw в viewport 1×1 настоящего AO attachment при каждом полном построении, перед геометрией. Пиксель уже очищен, поэтому результат AO не меняется. Полное построение предшествует любому частичному. Дополнительная стоимость: 1 draw, 3 вершины, 1 alpha-write на full rebuild; ноль новых attachments/dispatches. На partial frame эта поправка не добавляет работы.

C# Kern.Contracts, Kern.World, Kern.Tests.Editor и Kern.Tests.PlayMode после поправки компилируются (exit 0, без управления Unity; существующие CS1701 в зависимостях Contracts/PlayMode остаются). ArchitectureLinter --source-only: exit 0, 37 repository violations; обязательные boundary scans: пусто. Новый ShaderWarmupContractTests.RecordedAmbientOcclusionClearStates_HaveProceduralVertexInputs проверяет наличие production pass в привезённой трассе и отсутствие mesh vertex inputs. Load/Store регионального обновления всё ещё могут переносить всё поле: для текущего 4096×4096 ARGB32 это 64 MiB attachment, потенциально 64 MiB load + 64 MiB store, а не только 50 176 texels. Scissor не отменяет эту стоимость. Точная доля построения pipeline и attachment bandwidth в 274,9 мс не измерена: имеющийся отчёт показывает PlayerLoop 273 мс, а не время компилятора. Поэтому причинная интерпретация cold pipeline остаётся сильной гипотезой на основании добавленного first-use и трассы, а не замером всей задержки.

После этой дополнительной поправки пользовательский runtime не запускался; исчезновение провиса 274,9 мс и первоначальных 60 мс не подтверждено. Более поздние отчёты 95,3 / 37,7 / 125,0 мс также не объявляются решёнными этим изменением.
