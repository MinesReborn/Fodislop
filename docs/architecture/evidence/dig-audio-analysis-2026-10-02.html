Звук копания: проверка кода и существующих логов

Область: AudioPacket → ServerAudioEventManager → ServerAudioEvent.PlayAudio → AudioSystem.PlayAt → FmodAudioBackend.CreateVoice. Все эти вызовы выполняются синхронно внутри обработки сетевого пакета на основном потоке. Это не означает, что FMOD синхронно читает все сэмплы: автоматическая загрузка данных createInstance асинхронная, но время самого вызова и остальных native API входит в обработчик.

Доказательства

Logs/Diagnostics/Stalls/frame_stalls_20261001_234738.txt:57: sfx/bz 13,0 мс; робот-цель 2,7 мс; AudioPacket 78,0 мс. Замеры вложены и не складываются. Это предыдущий сеанс, подтверждающий вклад аудио и лишнего поиска робота, а не измерение нынешних 274,9 мс.

Assets/Plugins/FMOD/Resources/FMODStudioSettings.asset:473: AutomaticSampleLoading: 0. Ранее WaitUntilReadyAsync проверял HaveAllBanksLoaded и отсутствие AnySampleDataLoading, не инициируя sample load. Поэтому готовность могла быть опубликована с незагруженными сэмплами. FMOD загружает metadata отдельно от sample data; preload позволяет начать playback сразу: официальный Bank.loadSampleData. Создание первого instance может инициировать асинхронную загрузку: объяснение FMOD.

ServerAudioVisualPlayback.SetupSlotPosition вызывал GetOrCreateRobot для targetBot даже при slot == null. Для звука target нужен не для позиции, а для поворота отсутствующего визуала. RobotManager.GetOrCreateRobot при отсутствии робота создаёт его через scene factory. Это подтверждённая ненужная синхронная работа в AudioPacket.

Изменения

FmodAudioBackend запускает EventDescription.loadSampleData для event:/sfx/bz при ожидании startup-ready, один раз за жизнь backend. Опрашивает getSampleLoadingState до LOADED с UniTask.Yield и поддерживает прежнее ожидание прочих банков. Новых flushCommands / flushSampleLoading / spin wait нет. Ошибки запуска preload не скрываются. Две существующие startup-подписки не увеличивают native reference count повторно. StopAll снимает ровно одну preload-ссылку и сбрасывает состояние. Сэмплы удерживаются между one-shot событиями. Стоимость: sample memory одного события до teardown; фактический native memory delta без runtime не измерен. В кадре копания не добавлен loadSampleData.

Target robot разрешается только при существующем visual GameObject. Source position и визуальные события со слотом сохраняют прежнюю семантику.

getEvent, getInstanceCount, createInstance и start теперь отдельно записывают длительность в существующий FrameEventLog, если вызов занял хотя бы 2 мс. Это уточняет уже измеренный общий sfx/bz, не является самостоятельным исправлением. На обычном событии — восемь timestamp-чтений, без новых строк/аллокаций; строки появляются только при медленном вызове.
