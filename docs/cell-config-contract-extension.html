Расширение контракта конфигурации клетки

Что сейчас захардкожено в клиенте, почему это должно приезжать с сервера и какие поля для этого нужно добавить в CellConfigurationPacket.

1. Что контракт несёт сегодня

MinesServer.Networking.Server.Packets.Connection.CellConfigurationPacket — readonly record struct, LayoutKind.Sequential, Pack = 1, читается и пишется через UnsafeRead/UnsafeWrite. Размер фиксирован, поэтому любое новое поле меняет размер пакета и требует согласованной правки обеих сторон.

ПолеТипБайтЧто задаёт
PropertiesCellConfigProperties1 Флаги: Passable, Breakable, DropsShadow, ReceivesShadow, Blending, Glowing. Биты 6 и 7 свободны.
DistortionCellDistortionType1 Neutral / Cause / Block — участие клетки в искажении узлов сетки.
AnimationCellAnimationType1 None / Blinking / Shimmer / Rainbow.
AnimationSpeedbyte1Скорость анимации.
FrameOffsetbyte1Смещение кадра.
Colorint4Цвет миникарты.
ReliefGroupbyte1 Рельефная семья. Единственное поле вида, которое уже приезжает с сервера.

Итого 10 байт на тип клетки, 256 типов — 2560 байт за соединение.

2. Что клиент решает сам, хотя это данные о клетке

Ниже — всё, что классифицирует клетку по её типу внутри клиента. Столбец «в оригинале» — откуда то же самое берёт клиент Mines: CellRender.cellConfigs[id].

ЧтоГде в клиентеВ оригиналеПоследствие хардкода
Кто адресует сплошной лист атласа, а кто тайл на клетку TerrainSheetCatalog.IsContinuousSheet — явный список типов textureType == 1 (списки crysy и rocky) Новый тип клетки с сервера рисуется тайлами и разваливается на штампы, пока список не правят руками.
Кто участвует в кайме рельефа TerrainReliefRimCatalog — перечисление семей textureType == 1, семья — reliefType Семья уже серверная, а участие — нет. Разъезжаются два источника правды об одном и том же.
Размер участка листа в клетках выводится из размера подкартинки в атласе, делённого на размер тайла wx/wy (у кристаллов и скал 10×8), смещение dx/dy Период тайлинга задаёт размер PNG, а не замысел. У нас все листы 320×320, то есть 10×10, тогда как в оригинале период по вертикали 8.
Скруглённый силуэт MapCellConfigCatalog.IsRoundableLoose — список из 25 типов отдельная ветка вида Определяет и картинку, и физическую занятость для света: ошибка в списке меняет тени.
Дороги не перекрывают свет MapCellConfigCatalog.IsRoad свойства клетки Свободный бит в Properties есть, а признак живёт списком.
Постройки и искусственные блоки MapCellConfigCatalog.IsBuildingOrArtificialBlock, TerrainQuadBuilder.IsBuildingBlock blocky, textureType == 4 Гасит Glowing и исключает из декалей — то есть переопределяет серверный флаг клиентским списком.
Профиль анимации и фаза TerrainAnimationProfileCatalog.Get: FacetedCrystal, PrismaticCrystal и фазы XGreen=1 … XCyan=5 animType, animSpeed, dx2/dy2 Animation и AnimationSpeed в пакете есть, но клиент их частично переопределяет.
Декали: семья, доля клеток, раскладка вариантов TerrainDecalCatalog нет прямого аналога Плотность и состав декалей нельзя менять без пересборки клиента.

Главный симптом. Рельефная семья приезжает с сервера, а «кто тайлится» и «кто с каймой» — нет. Поэтому на вопрос «по какой системе тайлить» сегодня нет ответа в данных: он рассыпан по трём спискам в трёх файлах клиента, и сервер на него влиять не может.

3. Предлагаемые поля

3.1. Два свободных бита в Properties

БитИмяЗаменяет
1 << 6RoundedSilhouetteIsRoundableLoose
1 << 7TransmitsLightIsRoad

Размер пакета не меняется.

3.2. Новые поля

ПолеТипБайтЗначенияЗаменяет
TextureKindbyte enum1 Ground = 0, Sheet = 1, Block = 4, SandAutotile = 16 TerrainSheetCatalog и участие в кайме — одним полем, как textureType в оригинале
SheetTilesXbyte1период тайлинга по X в клеткахвывод размера участка из размера PNG
SheetTilesYbyte1период по Y
AnimationProfilebyte enum1 Default, FacetedCrystal, PrismaticCrystalTerrainAnimationProfileCatalog
AnimationPhasebyte1 индекс фазы, сегодня XGreen = 1 … XCyan = 5таблицу фаз в клиенте
DecalFamilybyte enum1 None, Stone, Sand, Road, GroundTerrainDecalCatalog
DecalPercentbyte1доля клеток с декалью, 0–100

Цена. Плюс 7 байт на тип клетки: 10 → 17. На 256 типов это 4352 байта, один раз за соединение. Пакет по-прежнему фиксированного размера и читается одним UnsafeRead.

Смещение dx/dy из оригинала не нужно. Там один общий атлас 128×128 тайлов, и участок надо адресовать абсолютно. У нас на тип клетки своя подкартинка, её начало уже известно из AtlasRect. Нужен только размер участка.

4. Порядок работ

  1. Расширить пакет в darkar25.fodinae.networking: два бита в CellConfigProperties и семь новых полей. Обе стороны обязаны обновиться вместе — размер структуры меняется, а декодер читает её одним блоком.
  2. Заполнить значения в дамми — DummyCellConfigurationUtilities становится единственным местом, где эти свойства задаются. Значения переносятся из клиентских списков один в один, без изменения поведения.
  3. Снять хардкод в клиенте: TerrainSheetCatalog, TerrainReliefRimCatalog, TerrainAnimationProfileCatalog, TerrainDecalCatalog, предикаты MapCellConfigCatalog — все читают конфигурацию клетки.
  4. Закрепить тестом, что каждый тип клетки сконфигурирован: сейчас это делает RequireEveryCellTypeConfigured, его надо расширить на новые поля, иначе незаполненное поле молча даст нулевое значение вместо ошибки.

Порядок обязателен. Пункт 2 нельзя сделать раньше пункта 1: пока пакет не несёт поле, перенос «на дамми» означал бы завести второй источник правды рядом с первым, а не убрать хардкод. Пункт 3 нельзя делать раньше пункта 2 — клиент останется без данных.
