Распространение света

Параметры находятся в LightingConfigHolder, файл VisualTuning.cs. Расстояние измеряется в клетках мира, отдельно для каждого RGB-канала.

Поглощение

sigmaEmpty = max(0, EmptyExtinctionRGB × EmptyExtinctionMultiplier)
sigmaSolid = max(0, SolidExtinctionRGB × SolidExtinctionMultiplier)
T = exp(-(sigmaEmpty × distanceEmpty + sigmaSolid × distanceSolid))
passedLight = incomingLight × T

T — оставшаяся доля света, а не яркость поверхности. Коэффициенты не обозначают проценты. Для заданной доли T на одну клетку коэффициент равен -ln(T).

Эти числа описывают путь через материал. Поэтому тесты проверяют также полный расчёт каскадов: формула сама по себе не исключает обход стены при выборе источников или смешивании проб.

PerPixel

DDA обходит каждый пересечённый texel базового уровня материала и учитывает длину пересечения. Occupancy не берётся из усреднённых mip-уровней. Частичная occupancy на физическом контуре задаёт доли пути в двух средах.

Каждая проба дальнего каскада соединяется с ближним интервалом собственным проверенным путём. Для пары интервалов применяется только линейное сложение:

radiance = nearRadiance + nearTransmission × farRadiance
transmission = nearTransmission × farTransmission

Это действует в обоих пиксельных режимах. Лимит старых шагов больше не разрешает пропускать геометрию. Динамические источники используют все каскады, а последний интервал покрывает поле. Порог MinimumTransmission больше не обрывает интегрирование. Результат ограничен конечным полем, угловым разрешением каскадов и точностью чисел; это не точная трассировка всех возможных направлений.

Источники

Фонарь создаёт излучение только в своей клетке. Радиусная маска, степень расстояния 1.5 и сглаженное окно удалены: они одновременно задавали скрытое затухание и создавали источники за препятствиями.

Излучение E определено как вклад одной однородной клетки. Для участка длиной d:

emissionWeight = (1 - exp(-sigma × d)) / (1 - exp(-sigma))
при sigma = 0: emissionWeight = d
radiance += transmissionBeforeSegment × E × emissionWeight

Это нормированный интеграл источника. Разбиение участка не меняет результат, а собственное поглощение светящейся породы не делит её яркость на 1600. Стена перед источником по-прежнему ослабляет его вклад. Для малых аргументов вычисление 1 - exp(-x) использует численно устойчивое разложение.

Поверхности, отражение и фон

Освещённая поверхность стены и прошедший через стену свет вычисляются отдельно. Отражение считывает свет со стороны попадания луча. Его реконструкция проверяет путь к каждой выборке; размытия через стену нет. Для отражения не используется отдельная рациональная формула затухания.

Ambient прибавляется один раз при выводе. Остаточный ambient за непрозрачной стеной не является прошедшим прямым светом. Диагностический режим Transmission всегда измеряет путь длиной одну клетку: изменение коэффициента больше не меняет одновременно расстояние измерения.

PerBlock

Клетка хранит падающий свет. При передаче соседу он умножается на exp(-sigma × d) материала исходной клетки. Собственное излучение solid выходит с его поверхности; внешний свет проходит поглощение. Четыре соседа задают путь по сетке. Число итераций определяется затуханием до относительного хвоста 10−6, с верхней границей по числу клеток, вместо фиксированных 20 шагов.

Проверки без Unity

dotnet run --project tools/Kern.LightingTests/Kern.LightingTests.csproj -- transport
dotnet run --project tools/Kern.LightingTests/Kern.LightingTests.csproj -- layout
dotnet run --project tools/Kern.LightingTests/Kern.LightingTests.csproj -- compile /path/to/glslangValidator

Первый стенд исполняет функции из текущего HLSL через float32 C++ и текстурные fixtures: путь через стену, смешивание каскадов с half-атласом, RGB, изменение масштаба, отражение, разбиение интеграла и PerBlock. Второй компилирует исходный C# с локальными заглушками для раскладки и передачи параметров. Третий отдельно компилирует HLSL; URP-преобразование вершины источника заменено заглушкой.

Эти проверки не запускают Unity. Проверка изображения и GPU-времени в Play Mode остаётся отдельной проверкой. Точный обход и проверенные соединения требуют больше работы, чем прежний марш с пропуском геометрии; счётчик стоимости показывает консервативную оценку шагов, а не измерение GPU.
