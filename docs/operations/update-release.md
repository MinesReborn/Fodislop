# Релиз обновления клиента

В репозитории клиента есть обработка `OutdatedClientPacket`: при получении пакета
клиент показывает причину отключения и открывает `UpdateURL`, если он задан.
Серверная конфигурация и фактические каналы публикации здесь не представлены,
поэтому их текущую настройку этот документ не подтверждает. Рантайм-ассеты
загружаются отдельным сетевым путём.

## Механизм: гейт версий

Клиент отправляет `ClientProtocolVersion.ClientVersion` в `ClientHello`. Офлайн-
соединение также сравнивает эту константу со своим минимумом и формирует
`OutdatedClientPacket`. `StatusProcessor` обрабатывает полученный пакет: передаёт
причину в отключение и пытается открыть `UpdateURL`. Настоящая серверная политика
и соответствие полей `config.json` коду сервера требуют проверки в репозитории
сервера.

Пакет `OutdatedClientPacket` из сетевого пакета содержит:

| Поле | Смысл в клиентском протоколе |
|---|---|
| `NewVersionCode` | Код новой версии, сериализуемый в пакете |
| `Name` | Имя, показанное клиентом |
| `Description` | Причина; клиент пытается разрешить её как ключ локализации |
| `UpdateURL` | Ссылка, которую клиент пытается открыть |
| `CLIArgs` | Дополнительная строка пакета; обработчик устаревшей версии её не использует |

Сетевой пакет задаёт формат сообщения, но сам по себе не подтверждает имена
параметров или поведение серверного `config.json`.

## Доставка по каналам

Код клиента задаёт сборки Windows, macOS, Linux, Android и iOS через
`Kern.Editor.BuildScript`. Он не описывает подключение SteamPipe, web-хостинг или
установщик; эти каналы нельзя считать настроенными только по этому репозиторию.

## Чек-лист релиза

В текущем клиенте `ClientProtocolVersion.ClientVersion = 7`, а
`PlayerSettings.bundleVersion = 1.0` (`ProjectSettings/ProjectSettings.asset`).
Это независимые значения: код не связывает протокольную версию с номером сборки.
Перед выпуском сверяйте протокольную версию с сервером и задавайте номер сборки
отдельно согласно правилам выбранного канала.

Сборщик Windows записывает `Build/Windows/Kern.exe`; параметры backend и
распространения в этом скрипте не задаются. Для Windows и macOS Unity вызывает
`ProductionServerEndpointValidator` перед сборкой: Development-сборки пропускаются,
а остальные отклоняются, если `DefaultUseDummyConnection` включён или compile-time
host/port не проходит проверку публичного endpoint. Валидатор проверяет константы
`ClientConfigurationDefaults`, не сохранённый конфиг пользователя, и не охватывает
Linux, Android или iOS. Это локальный pre-build gate, а не проверка доступности
сервера или server-side minimum version.

Серверный минимум и URL обновления нужно менять по инструкции серверного проекта,
после проверки совместимости.

## Почему апдейтер снесли

Историческое объяснение удаления апдейтера. Текущая реализация перечислена выше;
причины удаления и наличие внешних каналов доставки по исходникам клиента
проверить нельзя.

## Ограничения

- В текущем `ProjectSettings/ProjectSettings.asset` стоит
  `insecureHttpOption: 2` (HTTP разрешён). Из этого значения нельзя установить,
  какие серверные функции сейчас требуют HTTP.
