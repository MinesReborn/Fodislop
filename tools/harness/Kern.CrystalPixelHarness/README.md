# Попиксельная проверка анимации сбора кристалла

Harness сопоставляет два набора кадров PNG с одинаковыми именами. Он не меняет
размер изображения и проверяет все четыре канала каждого пикселя. По умолчанию
допускается ноль отличающихся пикселей. Для каждого кадра создаются PNG
теплокарты с ярко-розовым цветом каждого несовпавшего пикселя и полупрозрачные
наложения, а `report.json` содержит точные
счётчики, среднюю абсолютную ошибку и координату худшего пикселя.

PlayMode-захват проверяет значок и счётчик `2` по двум независимым иерархиям:
эталон собирается тестом по сохранённой структуре префаба, production — через
фабрики игрового кода. Проверка отдельно требует видимые пиксели значка и
счётчика; пустые захваты не могут пройти сравнением пустого кадра с пустым.
Также сравнивается каждый RGBA-пиксель всех кадров шести цветов. Сырые PNG
сохраняются в `source/` и `production/`; `paired/` — увеличенный в 4 раза методом
nearest-neighbor просмотр, эталон слева, production справа, жёлтый разделитель.
Увеличение применяется только к просмотру, исходные захваты не масштабируются
перед сравнением. `report.txt` содержит размер захвата, масштаб просмотра и итоги.

Масштаб значка закреплён по сериализованному Sprite asset: прямоугольник 12×12 px
и `m_PixelsToUnits: 16` задают размер `0.75×0.75` world units. Поле
`SpriteRenderer.m_Size = 0.12` из префаба не влияет на `Simple` draw mode.
Harness отдельно проверяет границы исходного и production Sprite. Экспортёр не сохранил сериализованный размер
TMP, поэтому fixture явно задаёт `0.5` и проверяет выходную высоту 8–12 пикселей
при 32 px на world unit. Это условие harness, а не доказательство утраченного
TMP-значения исходного клиента. Для этого значения нужен сериализованный TMP
компонент или захват исходного клиента при той же проекции.

## Съёмка

В Unity PlayMode доступен сценарий `CrystalCollectionPixelParityPlayModeTests`.
Запустить headless, когда Unity Editor закрыт:

```sh
unity test . --mode PlayMode \
  --filter TwoCrystalFlight_MatchesSourceSpriteCounterAndTimelinePixelForPixel \
  --output Logs/Diagnostics/CrystalPixelParity-test-results.xml \
  --timeout 600
```

Сценарий сам проверяет видимость значка и счётчика, сравнивает RGBA-кадры с
нулевым допуском и сохраняет исходные, production и парные PNG в
`Logs/Diagnostics/CrystalPixelParity/<id>/`. Отдельный comparer ниже нужен,
если сравниваются внешние захваты игры или другой набор кадров.

Сохранять нужно один и тот же изолированный эффект целиком: значок и счётчик,
включая прозрачность. Для исходного и проверяемого вариантов зафиксировать:

- одинаковые размеры кадра, камеру, проекцию, масштаб, цветовое пространство,
  фон и настройки рендеринга;
- одинаковые параметры эффекта, начальную точку и позицию робота-получателя;
- одинаковый фиксированный шаг симуляции и кадры в одинаковые моменты времени;
- все кадры от первого видимого кадра до завершения полёта.

Файлы именовать одинаково и по порядку, например `frame-0000.png`,
`frame-0001.png`. Не масштабировать, не кадрировать и не пересохранять кадры
через мессенджер: сравнение учитывает каждый RGBA-байт.

## Запуск

```sh
dotnet run --project tools/harness/Kern.CrystalPixelHarness -- compare \
  <reference-frames> <candidate-frames> <output-directory>
```

Код завершения `0` означает, что разница не превысила порог; `1` — что порог
превышен; `2` — ошибка входных данных. Порог можно задать явно:

```sh
dotnet run --project tools/harness/Kern.CrystalPixelHarness -- compare \
  <reference-frames> <candidate-frames> <output-directory> \
  --max-different-pixels 0
```

В `<output-directory>/diff/` сохраняются `*.diff.png` и `*.overlay.png`; полный
отчёт находится в `report.json`.

После PlayMode-захвата скормить получившиеся папки comparer-у:

```sh
dotnet run --project tools/harness/Kern.CrystalPixelHarness -- compare \
  Logs/Diagnostics/CrystalPixelParity/<id>/source \
  Logs/Diagnostics/CrystalPixelParity/<id>/production \
  Logs/Diagnostics/CrystalPixelParity/<id>/comparison
```
