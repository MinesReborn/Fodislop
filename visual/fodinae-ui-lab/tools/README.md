# Инструменты дизайн-системы

Карта. Прочитать раньше, чем запускать что-либо: файлов много, но одновременно
нужны почти никогда — они разложены по тому, **когда** их запускают.

Макет (`visual/fodinae-ui-lab/`) — источник истины для вида игры. Вид игры не
рисуется руками: он либо печатается из макета генератором, либо сверяется с ним
проверкой. Всё, что ниже, — про это.

---

## 1. Само, при каждой сборке

Ничего запускать не нужно: `node scripts/check-architecture.js` зовёт их сам и
падает вместе с ними.

| инструмент | что держит |
|---|---|
| `emit-uss-tokens.py --check` | токены игры совпадают с `css/tokens.css`, включая ось `fit` в `TokenUtilities.uss` |
| `emit-icon-textures.py --check` | PNG иконок побайтово совпадают с SVG макета |
| `compare-components.py --check` | 121 пара компонентов: покой, состояния (`:hover`), варианты (`--active`), ось текста и **молчание игры** — свойство, названное только макетом |
| `check-fit.py` | контракт `data-fit` перенесён в USS; порог `FLOOR` не даёт проверке замолчать |
| `lint-design-system.py` | токены, шкалы, контраст, протечка примитивов; долг по потолку |

Первые две **печатают** файлы игры без `--check`. Правка напечатанного файла
руками будет затёрта — правьте макет.

## 2. Руками, когда сомневаетесь

| инструмент | вопрос, на который отвечает |
|---|---|
| `check-cascade.py` | «я поменял только то, что хотел?» Снимает отпечаток каскада макета; `--save` принимает новое состояние. Не гейт, а инструмент до/после. |
| `inventory.py` | числа дизайн-системы без приговора: сколько чего и какими значениями |
| `measure-i18n.py` | насколько текст растёт при переводе; сколько узлов объявили поведение при нехватке места |
| `report-off-palette.py` | цвета USS, не совпавшие с палитрой точно (округлять нельзя — это перерисовка под видом порядка) |
| `computed-snapshot.js` | отпечаток вычисленных стилей в консоли браузера: проверить, что переезд объявлений ничего не изменил |

## 3. Когда макет перерисован заново

Порядок именно такой.

1. `extract-i18n.py --apply` — проставляет `data-i18n` по словарю игры.
   Идемпотентен, ключи выводятся, а не выдумываются.
2. **Руками**: `data-fit` на текстовых узлах по правилам `css/text.css`
   (`wrap` / `clip` / `clamp` / `shrink` / `atomic`). Это не автоматизируется:
   поведение при нехватке места — решение, а не вывод. `check-fit.py` уронит
   сборку, если пометок стало меньше порога.
3. **Руками**: `component-map.json` — пары «класс игры ↔ класс макета».
   Значение пары может быть составным: `mm-nav-tab--active` ↔
   `fdn-settings-tab.active`, `mm-tb--dim` ↔ `chronicle-item.past
   .chronicle-bead`. Так сверяются состояния и варианты — игра называет их
   отдельным классом, макет вторым классом на том же узле. Без такой пары
   вариант не проверяется ничем: активная вкладка настроек прожила золотой
   против бирюзовой в макете именно поэтому.
   Пара заводится, только если элементы занимают одно место и играют одну роль.
   Компонента, которого в игре нет, в карте быть не должно — это тоже ответ.
   `compare-components.py` скажет «нет правила» про каждую пару, потерявшую
   сторону.
4. `fit-easing.py` — если появилась новая `cubic-bezier`: в USS их нет,
   подбирает ближайшую из 23 именованных кривых Unity и печатает отклонение.
5. Прогон всей группы 1.

**Три ловушки сверки, каждая стоила по разъехавшемуся экрану.** Сокращения:
макет пишет `border: 1px solid X`, USS требует стороны, и пока они не
приводились к одному виду, ни одна рамка не сравнивалась вовсе. Молчание:
«игра не сказала — отдала теме» верно для наследуемого, но не для фона и
границы, и четыре коробки жили невидимыми. Составные узлы: игра собирает вид
из нескольких классов на элементе, и свойство, названное соседом, названо —
без разбора разметки это читается как пропуск.

**Чего эти проверки не ловят.** Переполнение текста — это результат раскладки,
и сверка правил его не видит по построению. Меряется вручную в браузере;
как именно и что нашлось в прошлый раз — `docs/design-text-overflow.md`.
Глазная проверка в Unity тоже ничем не заменяется: числа сходятся и при
неверном виде.

## 4. `derived/` — ответ уже доставлен

Разовые выводы: шкала прозрачности, семантические токены полупрозрачности,
покрытие инлайна утилитами, перенос инлайна в правила. Их результат давно лежит
в CSS и USS, и запускать их незачем — они сохранены как **обоснование**
конкретных чисел, а не как шаг конвейера. Смотреть, когда возникает вопрос
«почему ступеней именно столько».

## Что чем держится, одним абзацем

Словарь сверяется значениями (токены), растр — побайтово (иконки), вид —
свойство за свойством по карте пар (компоненты и их состояния), поведение
текста — по объявлению на узле (`data-fit`). Всё остальное — измерения без
приговора. Проверка, которой нечего проверять, обязана кричать, а не радоваться:
поэтому у контракта текста есть порог, а у долгов — потолок.
