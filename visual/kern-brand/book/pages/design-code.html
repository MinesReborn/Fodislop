01

Принципы

двенадцать правил

  1. Кадр 1920×1080, масштаб по высоте. Все размеры заданы для эталонного кадра; на устройстве кадр масштабируется целиком (Kern PanelSettings).
  2. Вид решает автор информации — Робот, Руки, Дело, Сеть. Один и тот же список выглядит по-разному, если его прислал сервер или записал игрок.
  3. Одна форма панели везде: базальт, рамка 1 px, срез правого верхнего угла 10 px, уголки по трём углам. Окна клиента и сервера не различаются формой.
  4. Оранжевый — только главное действие и тревога. Одно главное действие на окно. Выбранное, включённое, текущая вкладка — кость.
  5. Прямые углы. Все скругления — 0. Круг остаётся только у круглого по смыслу: навык, стик, кнопки геймпада.
  6. Глубина — линией, а не размытием. Тень — смещённая отбивка или линия по верху; размытых теней и стекла нет.
  7. Три шрифтовые роли, не смешиваются: заголовки и ник — Exo 2, Onest — текст, JetBrains Mono — числа, координаты, метки.
  8. Шкалы фиксированы. Кегли --t-0…17, шаг 2 px (--sp-N = N шагов), размеры элементов --ctl-*. Значения вне шкал — только с причиной в комментарии.
  9. Цвета-литералы — только в токенах. В компонентах — смысловые токены; прозрачность — через канал палитры: rgb(var(--rgb-well) / .45).
  10. Декор — только с данными или причиной из игры. Без слов в декоре: перевод и проверка переполнения ломаются.
  11. Ничего не пропадает. Телефон получает тот же состав, что монитор, — перекладкой: в меню ☰, иконкой с подсказкой, двумя строками чата.
  12. Данные не двигают соседей. Числа от 10 000 сокращаются не длиннее четырёх знаков (12K, 4.7M, 85B, 1.3T), клавиши не сжимаются по тексту, колонка одной ширины --col: 264px.

05

Движение

квант: показания, а не эффекты

Интерфейс меняется так, как меняются показания датчика робота: ступенями данных, быстро, без пружин и отскоков. Двигается только то, что сообщает изменение, — декоративного движения нет. Правила — kern-ui/css/motion.css, ступенчатые данные — kern-ui/js/motion.js.

Образец

Настоящий груз, прочность и окно макета. Кнопки проигрывают правила: ячейки загораются по одной, число досчитывается, переход порога 100 % — две вспышки, окно разворачивается из линии рамки.

Источникspecimen.html?c=motion

Принципы

  1. Движение несёт данные. Шкала, число, состояние, появление окна. Фон, рамки, микрографика и мир под HUD интерфейсом не двигаются.
  2. Квант, а не плавность. Ячейки и точки меняются по одной с шагом --step 20 мс; число досчитывается за --count 250 мс. Сколько изменилось — видно по тому, сколько ступеней прошло.
  3. Быстро. Отклик 80 мс, окно 120 мс, экран 200 мс. Ничего не задерживает игрока: управление доступно с первого кадра, анимация его не блокирует.
  4. Одна кривая — ease-out. Без back, elastic, bounce: у робота нет пружин. Перескок (бегунок, ячейка) — линейный.
  5. Нажатие — тоном в том же кадре. Без сдвига и масштаба: клавиша темнеет мгновенно, наведение — за 80 мс.
  6. Тревога — две вспышки и ровный цвет. Повторяется только при новом событии, никогда по кругу: мигающее без конца перестают замечать.
  7. Фокус перескакивает. Рамка фокуса (клавиатура, пад) не едет между элементами — она сразу там, где игрок.
  8. Движение можно выключить. Настройка «уменьшить движение» обнуляет все времена: те же состояния, без переходов, тревога — ровный цвет без вспышек.

Перенос в Unity 6.7

Проверено по сборке редактора 6000.7.0b4 (UnityEngine.UIElementsModule) и по руководству 6.7: USS transitions, справочник свойств, фильтры.

В макетеВ игреКак
Отклик: transition цветаUSS transition1:1. Цвет, фон, рамка, opacity — быстрый путь: геометрия не пересобирается
Окно: scale + opacityUSS transitionКласс is-entering снимается на следующем кадре (переход начинается только после первого кадра). scale, translate — без пересчёта раскладки; ширину и высоту не анимировать
Закрытие окнакласс + TransitionEndEventКласс закрытия, по концу перехода — display: none: display не анимируется
Квант: задержка --qd у каждой ячейкиstyle.transitionDelayЗадержку ставит код шкалы, как kernQuant. steps() в USS нет — ступени даёт сама ячейка, а не кривая
Досчёт числаschedule.Execute(…).Every(16)Как kernCount: значение по времени до --count, текст — каждый кадр
Тревога: @keyframes, 2 повтораanimation-name + UIAnimationClipВ 6.7 есть animation-name, animation-duration, animation-iteration-count: 2, animation-direction, animation-play-state; источник — ассет UIAnimationClip. Руководства по созданию клипов в бете нет — запасной путь: два переключения класса через schedule
Вспышка: opacity .25 ↔ 1USS opacity1:1, быстрый путь. filter для вспышки не берётся: он рисует поддерево в текстуру, а brightness() в списке фильтров 6.7 нет
Кривая ease-outtransition-timing-function: ease-out1:1; ease-out-back, -elastic, -bounce в 6.7 есть, но брендом запрещены
Выключенное движениекласс на корне панелиПеременные времени USS в 0 и снятые animation-name — та же схема, что :root.motion-off
—backdrop-filterНе используется: только URP и экранные панели, переходы не поддерживаются

Перенос в USS

css макета → ui toolkit

UI Toolkit принимает не всё, что умеет браузер. Таблица — как каждое средство макета переносится в игру. Цвета и размеры идут переменными 1:1, узоры и формы — текстурами и векторными картинками.

В макетеВ игреКак
Цвет, размер, кегль, времяПеременная USS1:1 из tokens.uss; полупрозрачные — уже собранными rgba()
rgb(var(--rgb-*) / a)Готовый цветВ USS нет подстановки канала: каждая прозрачность — свой токен
Срез угла clip-pathVectorImage или 9-sliceРамка панели со срезом — 9-slice спрайт; срез главной кнопки — тот же спрайт меньшего размера
Уголки --ticks, штриховка --hatch, точки --dotsТекстураУголки — в 9-slice рамки; штриховка и точки — повторяемая текстура фона (background-repeat)
Зерно --grainТекстураСтатичный шум 160×160, повторяется
box-shadowГраница или подложкаОтсвет сверху — border-top; отбивка окна — элемент-подложка со смещением 6/6 px
Сброс браузера, reset.cssне переноситсяв UI Toolkit стилей браузера нет; сброс держит макет на том же «голом» основании, что и игра

Медиазапросы S/M/L/XLКласс на корнеКлассы size-s…xl, in-touch, in-pad ставит код по размеру и вводу
:hover, :active, :focus, :disabledПсевдоклассы USSЕсть в USS 1:1; :focus-visible — :focus + класс ввода

Порядок переноса

  1. Перенацелить генератор tools/Kern.DesignSystem (Paths/Repository/DesignSystemPaths.cs) с удалённого visual/kern-ui-lab на visual/kern-ui и сверить его вывод с tokens.uss.
  2. Собрать FontAsset для Exo 2, Onest, JetBrains Mono (лицензии OFL лежат в kern-ui/fonts).
  3. Нарисовать 9-slice: рамка панели со срезом и уголками (окна и HUD), главная кнопка, табличка раздела.
  4. Перенести компоненты по системам: Руки → Дело → Сеть → Робот; после каждой — сверка с макетом снимком.
